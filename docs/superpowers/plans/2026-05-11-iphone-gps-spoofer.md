# iPhone GPS Location Spoofer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a CLI (`spoof.sh`) that generates a minimal Xcode project pre-wired with a GPX-based location simulation, deploys it to a USB-connected iPhone via `xcodebuild`, and instructs the user to unplug — leaving the iPhone spoofed until reboot.

**Architecture:** Thin shell driver writes a GPX file from CLI args, regenerates the Xcode `project.pbxproj` from a stable `project.yml` via xcodegen, ships a committed `.xcscheme` carrying `allowLocationSimulation="YES"` and `locationScenarioReference` pointing at the GPX, then invokes `xcodebuild ... clean build run` against the device UDID. Detection survives USB unplug because we never call `xcodebuild stop`.

**Tech Stack:** bash, xcodegen, xcodebuild, Swift (single-file minimal `UIApplicationDelegate`), GPX 1.1, macOS Xcode 15+.

**Working directory:** `/Users/alexey/Projects/gps-spoof/` (will become a git repo in T0).

**Boundaries:**
- `lib/gpx.sh` is the *only* place that knows GPX XML or coordinate ranges. `spoof.sh` calls it. Tests target it directly.
- The custom `.xcscheme` is **shared** (not user-specific) and **not** overwritten by `xcodegen generate` — xcodegen only writes auto-generated schemes when the YAML enables them; we mark our scheme as manually managed.
- `project.yml` is the source of truth for `project.pbxproj`; whenever the structure changes, regenerate. The GPX file is *referenced* but its bytes are rewritten by `spoof.sh` outside the project graph.

#!/usr/bin/env bash
# Pure functions for GPX generation. Source this file; do not execute directly.

# validate_coords <lat> <lon>
# Returns 0 if both are valid decimal numbers in range, non-zero otherwise.
validate_coords() {
  local lat="${1-}"
  local lon="${2-}"
  local num_re='^-?[0-9]+(\.[0-9]+)?$'

  [[ "$lat" =~ $num_re ]] || return 1
  [[ "$lon" =~ $num_re ]] || return 1

  # bash arithmetic can't do floats; use awk for comparisons
  awk -v lat="$lat" -v lon="$lon" '
    BEGIN {
      if (lat < -90 || lat > 90) exit 1
      if (lon < -180 || lon > 180) exit 1
      exit 0
    }
  '
}
```

# xml_escape <string>  — escapes &, <, > for XML text/attributes
xml_escape() {
  local s="$1"
  s="${s//&/&amp;}"
  s="${s//</&lt;}"
  s="${s//>/&gt;}"
  s="${s//\"/&quot;}"
  printf '%s' "$s"
}

# write_gpx <lat> <lon> <name> <out_path>
# Writes a GPX 1.1 file with a single waypoint. Overwrites if present.
write_gpx() {
  local lat="$1"
  local lon="$2"
  local name="$3"
  local out="$4"

  validate_coords "$lat" "$lon" || {
    echo "write_gpx: invalid coords: lat=$lat lon=$lon" >&2
    return 2
  }

  local esc_name
  esc_name=$(xml_escape "$name")

  mkdir -p "$(dirname "$out")"
  cat > "$out" <<EOF
<?xml version="1.0" encoding="UTF-8"?>
<gpx version="1.1" creator="GPSSpoof" xmlns="http://www.topografix.com/GPX/1/1">
  <wpt lat="$lat" lon="$lon">
    <name>$esc_name</name>
  </wpt>
</gpx>
EOF
}

if [[ -z "${TEAM_ID:-}" ]]; then

- [ ] **Step 1: Write the script**

```bash
#!/usr/bin/env bash
# spoof.sh — generate GPX, deploy to USB-connected iPhone, persist after unplug.
#
# Usage: ./spoof.sh --lat <lat> --lon <lon> [--name "Label"] [--udid <udid>]
#
# Env:
#   TEAM_ID  — Apple Developer team id for code signing (optional if Xcode already auto-signed once)
#
# Effect: iPhone reports the spoofed coordinates to all apps (Maps, Find My, Snapchat, etc.)
# until reboot. Do NOT stop the Xcode/xcodebuild process — just unplug the USB cable.

set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
# shellcheck source=lib/gpx.sh
source "$SCRIPT_DIR/lib/gpx.sh"

# --- arg parsing ---
LAT=""
LON=""
NAME="Spoofed Location"
UDID=""

usage() {
  cat <<EOF
Usage: $0 --lat <lat> --lon <lon> [--name "Label"] [--udid <udid>]

  --lat   latitude  (-90  .. 90)
  --lon   longitude (-180 .. 180)
  --name  optional waypoint label
  --udid  override device UDID (default: first connected iPhone)
EOF
}

while [[ $# -gt 0 ]]; do
  case "$1" in
    --lat)  LAT="${2-}";  shift 2 ;;
    --lon)  LON="${2-}";  shift 2 ;;
    --name) NAME="${2-}"; shift 2 ;;
    --udid) UDID="${2-}"; shift 2 ;;
    -h|--help) usage; exit 0 ;;
    *) echo "Unknown arg: $1" >&2; usage >&2; exit 1 ;;
  esac
done

if [[ -z "$LAT" || -z "$LON" ]]; then
  usage >&2
  exit 1
fi

# --- write GPX (validates coords) ---
GPX_PATH="$SCRIPT_DIR/GPSSpoof/GPSSpoof/locations/target.gpx"
if ! write_gpx "$LAT" "$LON" "$NAME" "$GPX_PATH"; then
  echo "ERROR: coords out of range. lat must be -90..90, lon must be -180..180." >&2
  exit 1
fi
echo "  ok   - GPX written: $LAT, $LON ($NAME)"

# --- find a connected iPhone ---
if [[ -z "$UDID" ]]; then
  # xctrace lists physical devices in: "iPhone Name (iOS Version) (UDID)"
  # Modern UDIDs are 25 chars with a hyphen (e.g. 00008110-001A347E0E33401E),
  # but older devices use 40 hex chars. Match both, prefer the first iPhone line.
  UDID=$(xcrun xctrace list devices 2>&1 \
         | grep -Ei 'iPhone.*\(([0-9A-Fa-f-]{25,40})\)$' \
         | head -1 \
         | grep -oE '\(([0-9A-Fa-f-]{25,40})\)$' \
         | tr -d '()')
fi

if [[ -z "$UDID" ]]; then
  echo "ERROR: no iPhone detected via USB." >&2
  echo "  - Plug in via USB and accept the 'Trust This Computer' prompt." >&2
  echo "  - Make sure the iPhone is unlocked." >&2
  echo "  - Run 'xcrun xctrace list devices' to verify it appears." >&2
  exit 1
fi
echo "  ok   - device: $UDID"

# --- build & launch ---
echo ""
echo "Building and launching on device (this can take 30-60s on first run)..."
echo "DO NOT interrupt this command. Wait for the 'App is running' line, THEN unplug USB."
echo ""

BUILD_LOG="$(mktemp -t gpsspoof-build).log"
trap 'echo "(build log: $BUILD_LOG)"' EXIT

# We use 'test-without-building' is NOT what we want. We need run-without-debug.
# xcodebuild does not have a "run" verb on its own; for device launch we use:
#   xcodebuild build && devicectl device process launch
# But on Xcode 15+, `xcodebuild ... -destination "id=$UDID" build-for-testing` then
# `xcrun devicectl device process launch` is the documented path.
#
# However, for location simulation specifically we need the LaunchAction's
# scheme settings to be honored, which means we have to use the *scheme* path:
#   xcodebuild -scheme GPSSpoof -destination id=$UDID build
#   xcrun devicectl device process launch --device $UDID com.local.gpsspoof
# devicectl alone does not apply the GPX. The GPX is applied by lldb/Xcode at launch.
#
# Reliable approach: use xcodebuild to build+install, then 'xcrun devicectl device process launch'
# does NOT inject GPX. The GPX injection happens via the debug session.
# Workaround: invoke `xcrun simctl` is sim-only. For device, we use:
#   open -a Xcode <project>; osascript to press Cmd-R   — fragile.
# Better: 'xcodebuild test' with our scheme — the test runner applies LaunchAction
# location settings on device. We don't have tests, so we use the simplest reliable
# path: build+install via xcodebuild, then launch with `xcrun devicectl` AND rely
# on the fact that the *installed* app reads location from the system, where the
# GPX has been injected by an attached debug session. The persistent-after-unplug
# behavior requires the lldb session, so we attach via xcodebuild's run-without-
# building path:

xcodebuild \
  -project "$SCRIPT_DIR/GPSSpoof/GPSSpoof.xcodeproj" \
  -scheme GPSSpoof \
  -configuration Debug \
  -destination "platform=iOS,id=$UDID" \
  ${TEAM_ID:+DEVELOPMENT_TEAM="$TEAM_ID"} \
  CODE_SIGN_STYLE=Automatic \
  clean build \
  > "$BUILD_LOG" 2>&1 \
  || { echo "ERROR: build failed. Tail of log:" >&2; tail -40 "$BUILD_LOG" >&2; exit 1; }

echo "  ok   - build succeeded"

# Install + launch with location-simulation honored.
# xcodebuild's 'install' copies the .app to the device. The GPX is applied by the
# debug launch (devicectl process launch --start-stopped + lldb) — but for
# persistence-after-unplug we want a debug session that *stays attached* until we
# unplug, then survives. That's exactly what Xcode.app's Run action does.
#
# Headless equivalent: use `xcrun devicectl device process launch --start-stopped`
# to get a stopped process, then attach lldb which reads the scheme's location
# scenario. Simpler: tell the user to open Xcode and hit Run — but we promised
# a one-command CLI, so we wrap it:

APP_BUNDLE_ID="com.local.gpsspoof"

echo "Installing .app on device..."
DERIVED="$(xcodebuild -project "$SCRIPT_DIR/GPSSpoof/GPSSpoof.xcodeproj" -scheme GPSSpoof -showBuildSettings 2>/dev/null \
  | awk -F' = ' '/ BUILT_PRODUCTS_DIR /{print $2; exit}')"
APP_PATH="$DERIVED/GPSSpoof.app"
[[ -d "$APP_PATH" ]] || { echo "ERROR: built .app not found at $APP_PATH" >&2; exit 1; }

xcrun devicectl device install app --device "$UDID" "$APP_PATH" >>"$BUILD_LOG" 2>&1 \
  || { echo "ERROR: install failed. Tail of log:" >&2; tail -40 "$BUILD_LOG" >&2; exit 1; }
echo "  ok   - app installed"

echo ""
echo "Launching with location simulation..."
echo ""
echo "    >>> A debug session is about to start. Wait until you see"
echo "    >>> 'Process N launched' or similar, THEN unplug the USB cable. <<<"
echo ""
echo "    Do NOT press Ctrl-C in this terminal."
echo "    Do NOT close the lldb session."
echo ""

# Launch the installed app stopped, then attach lldb so the LaunchAction's
# location scenario is applied and the debug session persists across unplug.
xcrun devicectl device process launch \
    --device "$UDID" \
    --start-stopped \
    "$APP_BUNDLE_ID" \
  >>"$BUILD_LOG" 2>&1 \
  || { echo "ERROR: launch failed. Tail of log:" >&2; tail -40 "$BUILD_LOG" >&2; exit 1; }

# Attach lldb interactively so the location scenario is applied and the debug
# session persists. The user unplugs USB while this is running.
echo "Attaching debugger (this is the session that holds the GPS spoof)..."
exec xcrun lldb \
  -o "platform select remote-ios" \
  -o "platform connect \"$UDID\"" \
  -o "attach --name GPSSpoof --waitfor" \
  -o "settings set target.process.location-scenario-file $GPX_PATH" \
  -o "continue"
```

> **Why the exec to lldb at the end:** The persistent-spoof trick depends on a live debug session being attached when USB is disconnected. iOS keeps the simulated location alive as long as the debug connection was active at the moment of unplug — disconnect just breaks the wire, not the session state. `xcodebuild ... run` is not a real verb; the closest we get from the CLI is build + install via `devicectl` + attach via `lldb`.
>
> **Open question for execution-time validation:** The exact lldb command to apply the LaunchAction's GPX may differ across Xcode versions. The plan ships the most common form; if it errors, fall back to opening the project in Xcode (`open GPSSpoof/GPSSpoof.xcodeproj`) and instructing the user to press Cmd-R once. Document the fallback in T11's README.

# gps-spoof

Spoof an iPhone's GPS location via Xcode's native GPX simulation. macOS only. Free Apple ID works. No jailbreak.

## How it works

Xcode's debug Run action can replace device GPS with coordinates from a GPX file. We ship a minimal iOS app whose only purpose is to provide a launchable target; the scheme carries `allowLocationSimulation="YES"` and points at a GPX file we rewrite on every run. While the debug session is attached, iOS reports the spoofed coordinates system-wide (Maps, Find My, third-party apps). Disconnecting USB does not end the debug session — iOS keeps the spoof until reboot.

## Prerequisites

| Requirement                              | Check                       |
| ---------------------------------------- | --------------------------- |
| macOS with full Xcode (not just CLI tools) | `xcode-select -p` ends in `Xcode.app/...` |
| `xcodegen` (recommended)                 | `brew install xcodegen`     |
| iPhone with iOS 15+, USB cable, trusted  | "Trust This Computer" tapped |
| Free Apple ID added to Xcode             | Xcode > Settings > Accounts |
| Location Services on iPhone              | Settings > Privacy > Location Services > On |

## First-time setup

```bash
./setup.sh
```

Then open `GPSSpoof/GPSSpoof.xcodeproj` in Xcode once. Pick your team under Signing & Capabilities so the device-signing handshake completes. Copy the 10-character Team ID from the dropdown and:

```bash
export TEAM_ID=XXXXXXXXXX
```

(Add to your shell profile if you'll use this often.)

## Usage

```bash
./spoof.sh --lat 37.3861 --lon -122.0839 --name "Mountain View"
```

Wait until the terminal prints that the debug session is attached, **then unplug the USB cable**. Do not press Ctrl-C. Your iPhone now reports the fake coordinates to every app.

## Restoring the real location

Reboot the iPhone. That's the entire reset — there is no daemon, no profile, nothing installed.

## Troubleshooting

- **"no iPhone detected"** — plug in via USB, tap "Trust This Computer" on the phone, unlock it, then re-run. Verify with `xcrun xctrace list devices`.
- **Signing error** — open `GPSSpoof/GPSSpoof.xcodeproj` in Xcode and set the team manually. `spoof.sh` prints the exact steps when this is the failure.
- **`lldb` attach fails or location does not change** — fallback: open the project in Xcode (`open GPSSpoof/GPSSpoof.xcodeproj`) and press Cmd-R once. Then unplug USB. Same end result.
- **iPhone reboots and location is real again** — that's by design.

## Tests

```bash
bash tests/test_gpx.sh
bash tests/test_integration.sh
```

Both run without a device.

## Caveats

- This tool exists for legitimate purposes (location-dependent app testing, privacy demos). Spoofing GPS to defeat fraud detection, evade legal monitoring, or violate the terms of services is your problem, not the tool's.
- iOS occasionally tightens the debug-location mechanism in major releases; if a future iOS breaks this, the fix lives in `GPSSpoof.xcscheme` and the lldb invocation in `spoof.sh`.
